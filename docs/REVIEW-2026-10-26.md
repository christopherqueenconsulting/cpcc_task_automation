## 1. TL;DR

What changed for grading, in seven bullets:

- **The reference solution is authoritative** (#414, #415). If you upload a solution, the model
  is told that what it does is required and nothing that matches it may be penalised. With no
  solution the rubric prompt is the same as master's (#414 body).
- **Each error type counts once**, and point bands in every rubric no longer overlap
  (#400 before rc1; #416 in rc1). Scores near a band edge can move.
- **Grading runs as a background job** with a live table, Cancel, Retry failed and "Use another
  model" (#430, rc3). On Streamlit Community Cloud results are no longer saved on the server.
- **Requirements can be checked against the solution** (#432) and a requirement error that
  duplicates a model error is now noted, and can be dropped (#437). Both ship in rc4. The
  drop is off by default.
- **Reasoning effort is chosen per run** (#425, rc2), and Setup can recommend one (#428,
  rc4, apply by hand only).
- **Output check (rc5, opt-in).** The grader can run each student's program in a local Docker
  sandbox on the instructor's test cases and compare the output with the solution's: the
  execution gate ([#434](https://github.com/christopherqueenconsulting/cpcc_task_automation/pull/434)) and its Setup page, Output column and drawer tab ([#444](https://github.com/christopherqueenconsulting/cpcc_task_automation/pull/444)). It is
  off by default, never shows on Streamlit Community Cloud, and `CQC_EXECUTION=off` hides it.
  With it off, scores should equal rc4 (rc5 CHANGELOG step 1; a check for you to run, not run here).
- **Dependencies moved (rc5).** pypdf 6.21.2 ([#449](https://github.com/christopherqueenconsulting/cpcc_task_automation/pull/449)) and a pymupdf major bump to 2.0 ([#441](https://github.com/christopherqueenconsulting/cpcc_task_automation/pull/441))
  that breaks `poetry install` on an Intel Mac. See open decision 8.

## 6. Harness findings

These affect the evaluation CI, not grading.

1. **A new suite poisons the fast path (#433).** The base capture ran one subprocess for all
   suites. A suite the base did not know made it exit non-zero, the base became empty, and
   every suite read "capture formats differ" and ran paid. Seen on #428, #429, #432. Fixed per
   suite in #433 (`6321194`). Until the fix reached master, new-suite pull requests paid the full run.
2. **The per-process fence key made `test-case-generation` never identical-skippable
   (#439).** Master's fence key was random per process, so two captures differed in 12 of 12
   cases, verified master against master. #428's A/B run
   [40055768563](https://github.com/christopherqueenconsulting/cpcc_task_automation/actions/runs/40055768563)
   failed on this noise. Lesson: any new nonce must be pinned in the request capture or its
   suite cannot be skipped. It cost a paid A/B on [#434](https://github.com/christopherqueenconsulting/cpcc_task_automation/pull/434) too: moving the fence helper changed
   the capture key, so every `test-case-generation` request differed from master's (12 of 12) and
   run [40063792568](https://github.com/christopherqueenconsulting/cpcc_task_automation/actions/runs/40063792568) failed at -0.038 on noise. Commit `5784c8c`
   made the nonce byte-identical to master's pinned one, and `prompt-eval/ab` then passed with
   "Requests identical to the base" at $0 (run [40064910872](https://github.com/christopherqueenconsulting/cpcc_task_automation/actions/runs/40064910872)).
   Check master-against-head capture equality per suite before READY on any pull request that
   touches fence or nonce code, and pin any new fence key in `request_capture._patched`.
3. **The `detect` job fast path trusts a head capture for `claude/*`, `auto/*` and
   untrusted-author pull requests** (#433 body). Those have no paid `ab` job. A hostile capture

   A/B always includes every suite its detection lists, so `project-feedback` rides along whenever

1. Fix forward on `master`: a revert pull request for the bad change, with a version bump and

4. Prompt, rubric and model changes change the key, so those re-grade on their own. A model
   rollback needs no code rollback: run `model-rollback.yml` or set `CQC_MODEL_GRADING=<previous model>`.
5. To switch off one feature instead of a whole release: `CQC_GRADING_JOB=off` (#430),
   `CQC_REQUIREMENT_OVERLAP=notes` or `off` (#437), `CQC_EXECUTION=off` (#429, #424, #434, #444: hides the whole output check).
