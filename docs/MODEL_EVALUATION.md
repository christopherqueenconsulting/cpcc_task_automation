# Model evaluation and automatic model updates

Which LLM grades student work is set in one file,
[`src/cqc_cpcc/config/model_registry.json`](../src/cqc_cpcc/config/model_registry.json).
Once a month a GitHub workflow looks for newer OpenRouter models, grades a synthetic
dataset with them and with the current default, and opens a pull request when a candidate
is clearly better or clearly cheaper at the same quality. That PR is merged by a guard
(when auto-merge is switched on) or by you.

**The app runs on your computer, so a merged change does nothing until you `git pull` and
restart.** The Home page shows a banner and an issue is opened when that is needed.

## Files

| File | Who edits it | What it holds |
|---|---|---|
| `src/cqc_cpcc/config/model_registry.json` | the bot (via PR) or you | model, reasoning effort, output budget and fallback per role; model capability profiles; previous models |
| `src/cqc_cpcc/config/model_policy.json` | **you only** (the guard rejects bot PRs that touch it) | vendor allowlist, provider privacy settings (ZDR), price ceilings, eval thresholds, grading freeze windows, which roles may be promoted automatically |
| `evals/datasets/v2/` | generated by `dataset_builder.py` | synthetic labelled cases, incl. validity, incomplete-program and requirement labels (see [`evals/README.md`](../evals/README.md)); v1 is frozen for the October 2026 calibration |

Roles: `grading` (rubric and exam grading), `digest` (very large submissions), `feedback`
(Give Feedback page), `flowgorithm`. Only `grading` changes automatically
(`auto_promote_roles`), because the dataset only covers grading. `digest` was removed in
October 2026: its prompt had never been evaluated, so promoting it on grading evidence
alone was unsafe. It goes back once the digest prompt suite passes (see
[`PROMPTS.md`](PROMPTS.md)).

## How a candidate wins

1. **Discovery** (free, no model calls): new or changed models from allowlisted vendors,
   under the price ceiling, with structured outputs, at least 400K context and 32K output,
   not expiring within 90 days, with a healthy endpoint, and affordable within the budget.
2. **Evaluation**: the current default and up to three candidates grade every case three
   times through the production grading code. Spend stops at $9 (hard cap $10, plus the
   eval key's own credit limit).
3. **Hard gates** (any failure blocks): call success rate, no refusals or truncations, no
   invented error ids, retry rate, every prompt-injection twin resisted, minimum F1 and
   score accuracy, latency, cost per submission, the model actually served, and policy.
4. **Promotion paths**:
   - *better*: composite score at least 0.03 higher (95% interval above zero), nothing
     else worse by more than 0.02, cost at most 1.5x;
   - *cheaper*: nothing worse by more than 0.02 and cost at most 0.7x.
   Paired bootstrap over cases, Holm-corrected across candidates. Ties keep the current model.
5. **Guard** (required check, fast feedback): re-scores the run's raw outputs against the
   labels and checks the PR only changes the registry and the report.
6. **Auto-merge** (only if `MODEL_AUTOMERGE_ENABLED` is `true`) is the real safety check. On
   master, with master's code, it repeats everything: the eval run is a successful master
   Model Evaluation run, the committed scorecard is byte-identical to its artifact, the
   winner re-derives from raw outputs, the registry equals exactly what the writer would
   produce, no grading freeze, at most one promotion per month, the model is still listed
   at the same price and version, and five recorded calls match OpenRouter's own
   generation records. Then GitHub merges once every required check is green. Any refusal
   is commented on the PR and relabelled `blocked-on-chris`.

## One-time setup (about 30 minutes)

1. **OpenRouter**
   - Create a key just for evaluations and set its **credit limit to $15 per month**.
   - In OpenRouter privacy settings, turn on **Zero Data Retention** for the account.
2. **GitHub App** (Settings > Developer settings > GitHub Apps > New)
   - Name e.g. `cpcc-model-bot`; no webhook.
   - Repository permissions: Contents read/write, Pull requests read/write, Issues read/write.
     **No Workflows permission.**
   - Install it on this repository; generate a private key.
3. **Repository environment** `model-eval` (Settings > Environments)
   - Deployment branches: `master` only. No required reviewers (they would block the cron).
   - Secrets: `OPENROUTER_EVAL_API_KEY`, `MODEL_BOT_PRIVATE_KEY`.
   - Variables: `MODEL_BOT_APP_ID`.
4. **Repository variables** (Settings > Secrets and variables > Actions > Variables)
   - `MODEL_BOT_LOGIN` = the app's bot login, e.g. `cpcc-model-bot[bot]`.
   - `MODEL_AUTOMERGE_ENABLED` = `false` (switch to `true` after two monthly cycles you
     have reviewed).
   - `MODEL_BOT_ASSIGNEE` = your GitHub username (issues are assigned to you).
   - Optional ClickUp mirror: secret `CLICKUP_API_TOKEN`, variable `CLICKUP_LIST_ID`.
5. **Branch protection** on `master`: add **`model-registry-guard`** to the required checks,
   keep required approvals at 0 (an App cannot approve its own PR), and keep the repository
   setting **Allow auto-merge** on (it is on today).

## Day to day

- **Try a model now**: Actions > Model Evaluation > Run workflow, enter candidates (e.g.
  `openai/gpt-6.1-sol` or `openai/gpt-6-luna@low`), keep *dry run* ticked to see the cost
  estimate first.
- **Roll back**: fastest is `CQC_MODEL_GRADING=<previous model>` in `.env` (or the
  Settings page pin) and restart. To record it in the repo, run Actions > Model Rollback.
- **Pause automatic changes**: set `MODEL_AUTOMERGE_ENABLED` to `false`, or add a window to
  `grading_freeze` in `model_policy.json`, e.g.
  `{"start": "2026-12-01", "end": "2026-12-20", "reason": "finals"}`.
- **Run locally**: `poetry run python -m cqc_cpcc.model_eval run --candidate <id> --dry-run`.

## What can go wrong and who hears about it

| Situation | What happens |
|---|---|
| Evaluation job fails or is cancelled | issue "Model evaluation needs attention", labelled `blocked-on-chris` |
| Current model fails a hard gate (drift) | same issue; nothing is promoted |
| Current model expiring or silently changed by OpenRouter | same issue; a replacement needs your merge |
| Monthly run did not happen (GitHub disabled the schedule) | weekly heartbeat opens an issue |
| Model changed on master | issue "Model change on master: git pull + restart" (+ ClickUp task if configured) |
| Auto-merge refused | comment on the PR explaining why, label switched to `blocked-on-chris` |
